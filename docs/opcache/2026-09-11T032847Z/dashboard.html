Runtime profiles

Apache and PHP-FPM use request-per-process PHP with OPcache. Swoole, FrankenPHP, RoadRunner, and Workerman use separate persistent-worker integrations. Reports remain separate because these execution models are not directly interchangeable.

Fairness controls

Targets and concurrency phases rotate between repetitions, and every route scenario must pass validation before measurement.

Framework scope

Full Stack, Micro, and Route Only describe how much application functionality the candidate supplies.

Application style

MVC/HMVC identifies frameworks presented through controllers or presenters in this benchmark. Other covers candidates whose benchmark integration does not use that pattern. The label describes this benchmark setup, not every pattern the framework can support.

Component-based

Yes means the project delivers independently installable first-party Composer components. This capability is separate from application style, so an MVC/HMVC framework can also be component-based.

Built-in DI

Yes means the framework itself ships dependency injection or a first-party service container. A container supplied only by the skeleton or another package does not count.

First-party router

Yes means the candidate supplies its own route registration and HTTP dispatch rather than relying on a direct PHP script or unrelated router package.

Filters

Selected facets use AND logic. Pure PHP is deliberately retained as the common baseline and does not participate in framework classifications.
